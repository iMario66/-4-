# Лабораторная работа №4. Процедурная декомпозиция

### ✅ 2. Цель программы, входы, результаты и самостоятельно определённые ограничения
* **Цель программы:** Рассчитать базовый тариф, ночной коэффициент, плату за багаж, общую сумму поездки, сумму на каждого человека и сдачу.
* **Результат:** На основе этих данных вывести в консоль статус поездки:
  * `DENIED_CAPACITY` — если пассажиров больше 4;
  * `PAYMENT_REQUIRED` — если пассажир внес сумму меньше необходимой;
  * `HIGH_SURGE` — если коэффициент повышенного спроса больше 1.5;
  * `COMPLETE` — во всех остальных случаях успешного расчета.
* **Входы:**
  * `distance` — весь путь в км (дробное число, BYN);
  * `duration` — время поездки в минутах (целое число);
  * `start_hour` — час начала поездки (целое число);
  * `passengers` — количество пассажиров (целое число);
  * `luggage` — количество мест багажа (целое число);
  * `surge` — коэффициент повышенного спроса (дробное число);
  * `payment` — сумма, внесённая пассажиром (дробное число, BYN).
* **Ограничения:** 
  * `distance`, `duration`, `luggage` и `payment` не могут быть отрицательными;
  * `start_hour` должен находиться в диапазоне от 0 до 23 включительно;
  * `passengers` — натуральное число (строго больше 0);
  * `surge` не может быть меньше 1.0.

#### Уровень 8. Сценарный анализ

Я взял в качестве значимого числового параметра surge. Базовый набор данных: dist = 10.0, dur = 20, hour = 14, pass = 2, lugg = 0, payment = 25.0.

А surge менял в следующем порядке: 1.2 -> 1.0 -> 1.6  
Обоснование: 1.2 - стандартный средний вариант. 1.0 - минимальный допустимый вариант. 1.6 - превышает порог 1.5, после которого статус меняется на HIGH_SURGE.

* **При surge = 1.2:**

  СТАТУС COMPLETE
* **При surge = 1.6:**

Результат изменился, так как total зависит от surge. А статус поменялся, так как если surge > 1.5, он меняется с COMPLETE на HIGH_SURGE.

#### Уровень 9. Автоматические проверки свойств

Четыре свойства для формулировки:
1. **Неотрицательность total:** Итоговый чек total никогда не будет меньше или равен нулю, так как даже при нулевой дистанции есть стартовая цена 3.5BYN.
2. **Монотонность стоимости от багажа:** При увеличении luggage стоимость total всегда будет расти и никто не будет уменьшаться.
3. **Корректность сдачи при успехе:** Если программа выведет статус COMPLETE/HIGH_SURGE, сдача автоматически больше или равна нулю.
4. **Предсказуемый рост тарифа от спроса:** При surge > 1.0 итоговая стоимость total в любом случае должна быть больше, чем базовая стоимость base.

Код для проверки свойств:
```c
void check_qualities(double night_coeff, double surge, double base, double luggage_fee, double total, double change, int status_flag){

    //first
    if(total > 0.0) {
        printf("Quality first: PASS\n");
    }
    else {
         printf("Quality first: FAIL\n");
    }

    //second
    double total_without_luggage = total - luggage_fee;
    if(total >= total_without_luggage) {
        printf("Quality second: PASS\n");
    }
    else {
         printf("Quality second: FAIL\n");
    }

    //third
    if ((status_flag == 2 || status_flag == 3) && change >= 0.0) {
        printf("Property 3 (Valid change on success): PASS\n");
    } else {
        printf("Property 3 (Valid change on success): FAIL\n");
    }

    //fourth
    double pure_cost_without_surge = base * night_coeff;
    double real_cost_without_luggage = total - luggage_fee;
    if (surge > 1.0 && real_cost_without_luggage <= pure_cost_without_surge) {
        printf("Property 4 (Surge effect check): FAIL\n");
    } else {
        printf("Property 4 (Surge effect check): PASS\n");
    }

}
```

Что вывелось на консоль при тесте:
* distance: 10
* duration: 20
* start_hour: 14
* passengers: 2
* luggage: 1
* surge: 1.0
* payment: 30

```text
Quality first: PASS
Quality second: PASS
Quality third (Valid change on success): PASS
Quality fourth (Surge effect check): PASS
```

#### Уровень 10. Мутационное тестирование

Мутационная версия функции total_foo:
```c
double mutant_total_foo(double base, double surge, double night_coeff, double luggage_fee) {
    return (base * surge * night_coeff) - luggage_fee; 
}
```
*(вместо плюса стоит минус)*

Проверка ошибки:
```c
bool run_mutation_test(void) {

    double base = 100.0;
    double surge = 1.2;
    double night_coeff = 1.0;
    double luggage_fee = 50.0;
    
    // Правильный расчет: (100 * 1.2 * 1.0) + 50 = 170.0
    double expected_total = 170.0; 
    double epsilon = 0.001;

    double mutant_result = mutant_total_foo(base, surge, night_coeff, luggage_fee);

    // Если мутант выдал НЕ 170.0 (а он выдаст 70.0 из-за минуса), тест его словит
    if (fabs(mutant_result - expected_total) > epsilon) {
        return true; // Мутант обнаружен
    }

    return false; // Тест не заметил ошибку

}
```
